# ADR 0006 — Private tracker and separately dated updates

14 October 2026. Implemented continuation of the user's selected option 3, adapted as a responsive web app in the existing Track 2B runtime. No replacement template, cloud deployment or new live-model claim.

Primary navigation is My votes / Upcoming votes / Search. A user explicitly tracks a vote; this never implies a Yes/No choice. A self-recorded choice and notes are optional. The first visitor has no fabricated private vote history. Tracking may remain only for the current visit, or the user may opt into an encrypted local vault. No private field is sent to public backend/model requests. Search filtering and perspective selection happen locally.

Private storage uses native Web Crypto PBKDF2-HMAC-SHA256 (600,000 iterations, random 16-byte salt) to derive a nonextractable AES-256-GCM key. Every write uses a fresh 12-byte IV and fixed authenticated format identifier. Only the version/KDF parameters, salt, IV and ciphertext are persisted under the app-owned localStorage key; case IDs, choice and notes stay inside authenticated ciphertext. The passphrase/key is not persisted. Reload locks, and hiding the page or five minutes without interaction locks the current key and removes private DOM state. Writes are serialized and cancelled if a lock changes the generation. Wrong passphrase, damaged ciphertext or unrecognized KDF metadata fail closed. Backup/import stays local and encrypted. No plaintext export of choices/notes.

This is a small implemented vault, not the full v0.1 proposed Argon2id/IndexedDB vault. Native PBKDF2 avoids introducing an unaudited cryptographic dependency during the deadline; the custom envelope/payload format is versioned separately. A forgotten passphrase has no recovery service. There is no account, sync, server private store or production security audit. Encryption at rest does not protect an unlocked tab, compromised app/browser/extension or weak passphrase. Removing a tracked item does not delete backups or prove secure erasure.

Public metadata adds five selected federal proposals: the reviewed original AHV case and four upcoming November 2026 entries. Labels are translated navigation metadata, not new Apertus-reviewed interpretations. Primary admin.ch and BSV page text was checked via web lookup; direct Python HTTP returned 403. The catalogue records manually captured primary excerpts and excerpt hashes, not invented original-HTML byte authentication. Data is a dated local snapshot, not a continuously refreshed full national registry.

The BSV implementation update published 5 October 2026 is a separately labelled official-source update, not a model completion, causal proof or amendment to the immutable March 2024 pre-vote case. Its planned December payment is not labelled an observed payment. The financing relationship has a named BSV source. No recorded update means no verified update in this snapshot, not proof of no real-world change. Other vote explanations/perspectives remain honestly unavailable until reviewed.

The original AHV Gate certificate, prompts, review packet and all failed traces remain unchanged. Source/date drawers preserve the five accepted statement wordings. Apertus remains visible as the actual extraction/actor-analysis component; encryption/privacy is an application/storage property, not an LLM capability.

Validation is recorded in the tracker-v2 evidence packet and design-qa.md. No current-law personalised calculation, voting recommendation, complete Swiss ballot coverage or production security certification is claimed.
