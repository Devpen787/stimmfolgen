# ADR 0010 — Local model with Docker app and isolated vote contexts

Date: 2026-10-15. Implemented on PR #4. Fresh clone/native model/Docker app proof and private two-case browser evidence are recorded in ../evidence/onprem-2026-10-15/REVIEW.md; second-case publication still awaits human review.

The on-premise route uses the pinned Apertus v1.5 8B MLX conversion on an Apple Silicon Mac and a non-root, read-only Node Docker app. The model binds only to literal loopback; Docker Desktop's host bridge reaches it without a public listener or tunnel. A launcher starts and stops only its own services, rechecks model bytes/identity and passes that fresh inspection read-only to the container. No hosted key, paid fallback or public Mac hosting is used. Setup needs network downloads; this is an on-premise design, not an air-gap claim. A clean isolated checkout/runtime is required before describing installation proof as complete. Reuse of already downloaded verified model bytes must be disclosed.

Native MLX does not provide the hosted API's schema-constrained decoding. Its local adapter therefore separates advice classification and plain English search. Routing/count metadata is application-composed; factual output remains the unchanged source ledger. Retrieval retains original question terms because the quantised model sometimes omits useful subjects in translation. Independent explicit service-policy checks refuse voting advice and observed later events. Rejected JSON/planning and attribution/source-page failures remain evidence. Hosted v10 interpretation is unchanged; local/hosted parity is not assumed.

Additional cases require source-byte and span validation plus an explicit human-user wording acceptance bound to the statement hash. The homeownership-tax packet is initially PENDING_HUMAN_REVIEW and does not enter the public case registry merely because model output exists. Model passage selection and engineering source checks do not masquerade as a human decision. The booklet's editorial cutoff is separate from verified retrieval/public availability; its mode is DOCUMENT_EXPLANATION, not proof of exact-byte pre-vote public availability. Later official results remain separate updates.

Public APIs and inference resolve an allowlisted case from a public query parameter, while the JSON body still permits only the question. Unknown cases fail instead of silently falling back to AHV. Each browser vote owns its own in-memory question/result state; asynchronous results cannot be carried into another vote. Saved notes pin the source for their own vote, including when tracking from Search rather than the reader. Private data is never attached to model calls.

Ordinary screens use plain-language descriptions, sources, dates and uncertainty. Trial notes, model-task codes, hashes and receipts belong in repository evidence/judge documentation, not the reading flow. The explanation starts with the proposal before the optional AI question. Necessary hosting/privacy and model fallibility disclosures remain. Video is outside this change.
